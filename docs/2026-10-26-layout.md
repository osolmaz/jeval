# Where judges, runs, eval sets and experiments live

## TL;DR

Everything a measurement depends on now has one defined place. A judge is one file that holds every text the model
reads. A run is one folder that records what ran and every request exactly as it was sent. An eval set is one file kept
with its private data. Experiments that ask other questions over the same evidence are a command, `rejudge`, not a
script outside the repository, and `compare` scores runs side by side.

## Why

During the first experiments with the legal judge, a run's trace recorded the domain's version but not the texts the
model read, so a request could only be rebuilt from code, and a prompt change without a version bump would have gone
unnoticed. Variants of the judge lived as extra domain names on branches or as scripts outside the repository, and the
eval sets were folders and id lists that only those scripts knew.

## The layout

| Thing                                                                                                          | Place                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A judge: the process and stage texts, the rubric rules, the questions asked about every item, gathering limits | One file in `judges/`. Its SHA-256 over the parsed content names it in the run's version, the trace and `run.json`. A variant is another file                                                                 |
| What the model read                                                                                            | `requests.jsonl` per case: every request as sent, with its result                                                                                                                                             |
| A run                                                                                                          | One folder: `run.json` with the domain, judge, model, limits, set, switch commit, the run its evidence came from, times and totals, then `cases/<id>/` with `result.json`, `trace.jsonl` and `requests.jsonl` |
| An eval set                                                                                                    | A set file with the set's name, its case folders, its labels and its scheduled ids, kept with the private data                                                                                                |
| An experiment on the same evidence                                                                             | `switch rejudge --from <run> --judge <file>`: the recorded steps are repeated and only the judging goes to the model                                                                                          |
| A comparison                                                                                                   | `switch compare <runs…> --set <file>`: every run scored on the cases that all of them answered                                                                                                                |

An item's verdict comes from the judge's questions: each question counts for the item or against it, and the item
passes only when every question for it says yes and every question against it says no. Meets and misses is two
questions, one of each kind.

The change was a hard cutover: `--domain`, `--steps`, `--options`, `--labels` and `--cases` are gone from the
commands that run or score, and the old flat result folders are not read. The requests that the legal judge builds
for a real case are byte for byte the same as before the change.
